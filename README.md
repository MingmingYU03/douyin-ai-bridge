# 把 AI 接进抖音：一份只读方案的真机踩坑记录

---

## 为什么写这个

我让一个 AI 通过 CDP 操控一台常驻的真 Chrome，能搜抖音、刷推荐流、还能真正看到视频画面。做完之后回头看，**真正花时间的不是"怎么连上 CDP"（这一步十几行就完了），而是十几个不查不知道、一查全是坑的细节。**

搜了一圈，做同一件事的项目已经有好几个（见文末），但大多只写"怎么用"，不讲"哪里会卡住"。那份卡住的时间，我补在这里。

账号是我自己的，已实名。**这套东西只读，不发布、不评论、不发私信**——不是做不到，是刻意不做。

---

## 三个反直觉的发现

如果只记三件事，记这三件：

**1. 视频下载地址不在 DOM 里，而且在 `RENDER_DATA` 里，还只在弹窗页里。**

`document.querySelector('video').currentSrc` 拿到的是 `blob:`（MediaSource），外部拿不到。真正的带签名直链藏在服务端注入的 `RENDER_DATA` 里——**但直接打开 `/video/<id>` 是拿不到的**，页面能加载、标题也对，里面偏偏没有播放地址。要换成：

```
https://www.douyin.com/jingxuan?modal_id=<aweme_id>
```

这个页面里才有。这个差异害我折腾了很久才想通。

**2. 登录框和身份验证框，不吃任何模拟输入。**

`Input.insertText` 能写进去，紧接着 React 重渲染就清空；`Input.dispatchMouseEvent` 点击也不触发。不是坐标不对——我用 `elementFromPoint` 确认过，点就落在那个文字上。

结论：**扫码 + 短信验证这一关必须人手动过。** 想靠自动化绕过是浪费时间，过后设备会被记住，只疼一次。

**3. CPU 被吃满的时候，你连 SSH 都进不去。**

表现很迷惑：`ping` 通、`nc` 端口能连上、但 SSH 卡在 `banner exchange timed out`，云助手的命令也一直"停止"状态。

原因不是网络：`sshd` 已经在 `accept()` 排队，只是轮不到 `write()` 发 banner。Chrome 自动播放视频一直在解码，把 CPU 榨干了。

## 踩坑清单

按"会不会浪费一整天"排序。全部是真机验证过的。

| 现象 | 原因 | 处理 |
|---|---|---|
| 直接弹点选验证码 | `--headless` 被识别 | 必须 `Xvfb` + 有界面 Chrome |
| 视频黑屏 / 不出画面 | Chromium 不带 H.264 | 换 `google-chrome-stable` |
| 9222 端口起不来 | 缺参数 | 加 `--no-first-run --no-default-browser-check` |
| 杀了 Chrome 但新实例行为诡异 | 子进程残留 | 杀全部进程，别用 `pkill -x chrome` |
| 强杀后起不来 | 残留 Singleton 锁 | 删 `<profile>/Singleton*` |
| 重启就掉登录 | `--user-data-dir` 在 `/tmp` | 挪到 `/root/...` |
| 页面全是方块 | 没装中文字体 | `apt install fonts-noto-cjk`，**装完要重启 Chrome** |
| SSH 握不上手，云助手也不响应 | CPU 被 Chrome 吃满 | `CPUQuota=150%` + 禁自动播放 |
| Chrome 随机崩 | `/dev/shm` 太小 | `--disable-dev-shm-usage` |
| 长视频抽帧跑到天荒地老 | `fps` 滤镜要全片解码 | `-ss` 放在 `-i` 前面，只解关键帧 |
| VNC 网页能开、一连就断 | 少了 `x11vnc` 或 `websockify` | 两个都要写进开机脚本 |
| 令牌死活不对，长度却一样 | 人工抄写字形混淆 | `W`→`M`、`l`→`1`；比 `sha256` 前 12 位，别用肉眼 |

最后一条值得单独说：43 个字符里错两个，长度完全一致，肉眼绝对看不出来。我们排查了两小时，最后是拿哈希对比才定位的。**令牌不要人工传递，放文件里让程序读。**

## 两个真实的教训

**教训一：别用 `cmd /c` 转发参数。**

最常见的写法是这样，它有命令注入：

```python
subprocess.run(["cmd", "/c", "tool.cmd"] + args)   # ✗ 参数里的 & 会变成命令分隔符
```

参数来自 HTTP 请求，`%26` 就是 `&`，等于把 shell 交出去了。改成直接起解释器、`shell=False`，问题消失。

**教训二：给 Chrome 留出 CPU。**

`systemd` 里加 `CPUQuota=150%` 是这套东西里救过命的一行。不给上限，它能让你连"进去改配置"的机会都没有，只能强制重启——而重启会清掉 `/tmp` 里的登录态，白扫码一次。

## 边界

- 账号自己的、实名自己的，动一下都算这个人的行为
- **不发布、不投草稿、不评论、不发私信**。代码里没有这些能力，比"有但不调用"可靠
- 令牌等于钥匙，别进仓库、别进日志、怀疑泄露就重新生成
- 频繁自动化可能触发风控，这个风险自己担
